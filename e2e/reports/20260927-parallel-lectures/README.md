# Параллельные лекции — нагрузочные прогоны 27.09.2026

Тест проведён на отдельном Compose-стеке, без нагрузки на публичный стенд. Основа —
`c2c504c` с исправлением запуска импорта после коммита и пакетной выдачей первого
SSE-снимка из текущего рабочего дерева. Созданы 10 разных преподавателей, курсов,
презентаций и активных лекций. В каждой презентации пять тестовых слайдов.

Генератор — фиксированный `lecturer-k6-sse:1.1.0`; 150 студентов на секцию, один
SSE-поток и загрузка PNG на каждого. При плавном входе интервал между виртуальными
студентами составлял 50 мс: 1500 входов примерно за 75 секунд. Затем во всех секциях
одновременно переключались слайды 2, 3, 4 и 5 с интервалом 10 секунд; все команды
преподавателей возвращали HTTP 200. `stream_complete` означает, что один клиент
увидел все четыре переключения без повторного подключения.

Для прогона `control` проверена изоляция: все 7465 полученных снимков содержали код
своей лекции; в последнем прогоне — все 7500 снимков. При 1500 клиентах измерено
около 1 ГиБ памяти core, 90 МиБ у PostgreSQL
и 11 соединений с базой. На машине Docker доступно 12 CPU и 7,65 ГиБ памяти.

Разбор ошибок `workers10` выявил ответы со статусом 0 и `dial: i/o timeout` при
соединении генератора через опубликованный порт Docker Desktop. Это сбой установления
соединения на тестовом сетевом пути; приложением в этом прогоне не возвращались 429
или 5xx. Переход к внутренней сети убрал неудачные входы и загрузки PNG. На ней
штатные четыре SSE-работника дали лучший результат, чем десять; оснований
увеличивать значение по умолчанию нет. Плохие
прогоны через host NAT сохранены: они показывают, что на основании одного успешного
прогона нельзя обещать стабильную работу публичного пути.

30-минутный прогон `k6-10x150-soak30m` во внутренней сети дал 1500/1500 входов и
первичных открытий SSE, 4491/4491 загрузок PNG и снимков своей лекции без ошибок
HTTP/SSE. У core после 5, 10, 15, 20 и 25 минут было примерно 1,09–1,10 ГиБ
памяти; в эти моменты сохранялось 1497 соединений. Измерения сохранены в
`soak-resources.csv`. Одноразовые k6-потоки закрылись после серверного тайм-аута
30 минут до последнего запланированного переключения, поэтому показатель
`stream_complete` для этого прогона равен 0/1500 и не служит оценкой работы
браузерного переподключения. Его при 1500 клиентах отдельно не проверяли.

При проверке через локальный Caddy все 1500 входов завершились, однако за отведённые
180 секунд полный сценарий успели закончить только 299 виртуальных участников;
остальные 1201 были прерваны генератором. 1495/1495 PNG и p95 1048 мс относятся
**только к этим 299**. Нулевой код завершения k6 не означает успешный прогон:
пороговые метрики учитывали лишь завершившиеся сценарии. Этот замер не устанавливает
предельную ёмкость Caddy, но не подтверждает 10×150 через прокси.

Ограничения: небольшие тестовые слайды, один инстанс core, без измерения публичного
туннеля, тяжёлых реальных презентаций и рассылки через MAX. `stream_complete`
строже поведения веб-клиента, который умеет переподключать SSE и опрашивать снимок
при обрыве. 10×150 следует указывать как результат теста изолированного ядра, а не
гарантированную ёмкость публичной установки.

JSON-файлы рядом — исходные метрики k6 без кодов лекций, токенов и персональных
данных. Тестовые учётные записи и локальные архивы за пределы стенда не переносились.

После исправлений прошли `ContentImportCommitTest`, `ContentIntegrationTest`,
`StudentSseBroadcasterTest`, `ParallelLectureIntegrationTest` и
`StudentIdentityIntegrationTest`. Maven запускался вне файловой песочницы, потому
что Mockito/Byte Buddy подключает локальный Java agent.
