# Презентация и сдача Lecturer Assistant

**Единственный актуальный файл для авторов презентации. Обновлено 30.09.2026.** Команда «ХАМЛ» уже провела живую лекцию на публичном стенде: преподаватель управлял занятием, студентка участвовала через мини-приложение MAX. Во время совместного теста проверялись слайды, вопросы, проверки и синхронизация устройств. Найденные ошибки повторного входа, дублирования студента и синхронизации исправлялись; после перепроверки владелец сообщил, что сценарий работает. Это проведённая лекция со студенткой в MAX, а не одна проверка входа преподавателя. Отдельный протокол с датой, устройствами и результатом каждого шага пока не оформлен.

## Что сдаём и куда

По последнему сообщению организаторов: **дедлайн 30 сентября 2026, 12:00 МСК**, PDF или ZIP **до 50 МБ**. Имя файла: `Хакатон MAX - Образовательные решения - ХАМЛ.pdf` (или `.zip`). Ранее кабинет показывал 18 МБ; новый лимит указан в сообщении организаторов. На первом служебном слайде — бот MAX, Git-репозиторий с полным commit hash, адрес API, тестовый доступ и порядок проверки. Исходники разрешено передать ссылкой на Git с hash. Для открытой публикации подготовить копию без пароля.

После дедлайна сданную версию кода и презентацию менять нельзя до результатов онлайн-этапа.

Исходники: [GitHub](https://github.com/MrHolly0/lecturer-assistant-v2). Для служебного слайда взять полный SHA опубликованной версии (`git rev-parse HEAD`) из итогового сообщения владельцу. Внутри репозитория ссылки относительные и открываются в выбранной ревизии; полный hash на слайде фиксируется после публикации.

Не помещать действующие секреты в Git или публичный PDF. Пароль преподавателя находится в отдельном локальном приватном листе владельца.

### Текст и факты для продуктовых слайдов

**2. Резюме:** «Студент открывает лекцию в MAX, видит текущий слайд и приватно сообщает, понятен ли он. Преподаватель получает сигналы и вопросы во время объяснения, запускает короткую проверку и после занятия видит итог». Не заявлять рост успеваемости как уже измеренный эффект.

**3. Проблема:** устный вопрос «всё понятно?» не показывает, на каком слайде и у какой части аудитории возникло затруднение. Поднятая рука публична, отдельная форма отрывает от лекции. Это гипотеза команды; интервью с преподавателями и студентами пока не проводились. Уместный пример — несколько учебных групп на одной лекции.

**4–6. Наблюдаемый сценарий:** преподаватель показывает PDF/PPT/PPTX/ODP в отдельном окне проектора. Студент входит через MAX, получает текущий слайд без обновления страницы, отправляет «Понятно», «Есть вопрос» или «Не понимаю» и задаёт вопрос. Преподаватель видит реакцию, отвечает лично или аудитории, запускает вопрос из банка или быстрый вопрос. После закрытия проверки доступны распределение и правильный ответ. Пауза блокирует действия и исключается из активного времени. После завершения доступны итог, история, группы и аналитика студентов. Преподаватель может управлять лекцией с телефонного пульта в MAX: менять слайды, ставить паузу, работать с вопросами и проверками, завершать занятие. **Живую лекцию с реальной студенткой команда уже провела и после исправлений перепроверила работу.** Для иллюстрации использовать только достоверные кадры соответствующих шагов.

**7. Архитектура:** `MAX/браузер → HTTPS/Tuna → Caddy → React/nginx → Spring Boot → PostgreSQL`; отдельно `Spring Boot → Python-конвертер → LibreOffice/Poppler → PNG и текст`; `MAX Bot API ↔ max-adapter ↔ core`. Сервер проверяет подпись `initData`, связывает повторный вход с MAX `user.id`; обновления слайда передаются через SSE. Хранятся аккаунты и роли, группы, презентации, участие, сигналы, вопросы и ответы. Пароли хешируются BCrypt, доступ к курсам проверяется сервером. На стенде — тестовые данные. Не заявлять изоляцию вузов, шифрование базы или автоматическое удаление данных как готовые функции.

**8. Проверки — выбрать 2–3 факта:** 131/131 backend-тестов прошли 27.09; отдельный технический прогон на `12856ce` дал 150/150 SSE-подключений и 22 500 событий; четыре Docker-образа основного MAX-стека собраны без кэша за 46,01 с при уже загруженных базовых образах. После выкладки 27.09 сайт и `/health` отвечали 200, восемь API-сценариев прошли. Изолированное ядро на `ab0bcee` прошло 10 лекций × 150 студентов, но полный путь через локальный Caddy завершили только 299/1500 сценариев за 180 с: **не заявлять доказанную публичную ёмкость 1500**. Это технические проверки, не пилот в аудитории.

**9. Пилот:** один вуз, отдельная управляемая установка, администратор и преподаватель. Сначала интервью и базовая лекция без продукта, затем 2–3 лекции той же группы с продуктом. Измерять долю подключившихся и отправивших сигнал, участие в проверках, время реакции преподавателя на рост «Не понимаю», p95 доставки слайда, долю лекций без технического сбоя. Пилота ещё не было; две–три лекции дадут предварительный сигнал пользы, не доказательство роста успеваемости.

**10. Масштабирование и границы:** сейчас одна установка рассчитана на одно учреждение; для следующего вуза разворачивается такая же отдельная установка со своей базой, файлами и настройками. Единый сервис возможен после реализации и проверки изоляции учреждений в пользователях, правах администратора, курсах, группах, файлах, аналитике и резервных копиях. Персональный конспект, исторический состав групп и LMS — будущие шаги. Базовый телефонный пульт уже есть. Детекции списывания нет.

## Что авторам взять у владельца

1. Состав команды и роли для слайда 2. Не переносить телефоны и почты участников из окна заявки в презентацию.
2. Пароль тестового преподавателя из приватного листа — только для закрытого технического слайда. В открытой копии его удалить.
3. Реальные кадры **проведённой лекции**: экран студентки внутри MAX, презентер преподавателя, проверка после закрытия, итог; по возможности пульт преподавателя в MAX. Скриншоты старых сборок и mock-интерфейса нельзя выдавать за финальный живой MAX-прогон. Если из записи нельзя достоверно извлечь кадр конкретного шага, переснять этот шаг на стенде.
4. Итоговый опубликованный commit hash и подтверждение, что стенд ему соответствует. Дедлайн из сообщения организаторов — 30.09.2026, 12:00 МСК.

На проверку отдать владельцу один редактируемый исходник и PDF до 50 МБ. Перед отправкой открыть PDF на другом устройстве, проверить ссылки и читабельность. Первый слайд закрытой версии должен содержать действующий пароль; публичная копия должна быть без секретов.
