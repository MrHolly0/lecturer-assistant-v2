Ты отвечаешь за интерфейс проекта `lecturer-assistant-v2` на хакатоне MAX. Дедлайн отправки — 30.09.2026, до заморозки функций 27.09 вечером.

## Контекст

Каталог `web/`: React 18, Vite, TypeScript, TanStack Query, Tailwind, Radix, компоненты в `src/shared/ui`, типы API генерируются из OpenAPI командой `npm run gen:api`.

Одна сборка обслуживает всех: мини-приложение студента, рабочее место преподавателя, презентер и экран проектора. Внутри MAX это мини-приложение, вне MAX — обычный сайт для разработки и проектора.

Продукт: преподаватель ведёт лекцию, студенты в MAX видят текущий слайд, шлют сигналы понимания, задают вопросы и отвечают на вопросы-проверки.

Обязательно прочитать до начала:

- `docs/hackathon/PROJECT_BRIEF.md` — общая картина.
- `docs/hackathon/research/MAX_API_NOTES.md`, разделы 2 и 3 — MAX Bridge, `initData`, `start_param`, ограничения платформ.
- `docs/hackathon/research/DEFECTS.md` — дефекты D-06, D-07, D-17, D-19, D-20, D-22, D-24, D-25 относятся к фронтенду.
- `docs/hackathon/TEAM_TASKS.md` — формулировки задач F-01…F-16.

## Границы

Твой каталог: `web/`. Каталоги `core/`, `adapters/`, `deploy/`, `openapi/` не трогаешь — там работает бэкенд параллельно. Типы обновляешь генерацией из OpenAPI, руками `src/app/api/schema.ts` не правишь.

Во `web/src/pages/PresenterPage.tsx`, `web/src/styles.css` и `web/src/widgets/PresenterSidePanel.tsx` есть незакоммиченные правки владельца проекта. Разобраться с ними до начала работы: закоммитить или отложить, но не потерять.

## Правила

- Ветка на задачу: `feat/F-04-student-live-screen`. Коммит начинается с номера задачи.
- Контракт API зафиксирован (таблица ниже). Пока эндпоинта нет на сервере, работаешь против заглушки в слое `src/app/api`, а не ждёшь бэкенд.
- Никаких секретов и токенов в коде и в репозитории.
- Каждый экран проверяется на ширине 375 и на компьютере. Кнопки не меньше 44×44, контраст текста не ниже 4.5:1.
- `npm run lint` и `npm run build` проходят без ошибок перед тем, как сказать «готово».
- Если задача занимает больше половины дня или упирается в неизвестное — пишешь оркестратору сразу.

## Очередь работ

**День 1 (18.09)**

1. **F-01, слой MAX.** Подключить `https://st.max.ru/js/max-web-app.js`, обёртка над `window.WebApp`: платформа, тема, `BackButton`, `ready`, безопасные отступы. Режим без MAX для браузера. Учесть из справки: `SecureStorage`, `DeviceStorage` и `HapticFeedback` не работают в веб- и десктопной версии, `MainButton` в MAX нет.
2. **F-03, продление токена.** Дефект D-06: сейчас при 401 токен стирается без попытки `/auth/refresh`, преподаватель вылетает посреди лекции. Один запрос на обновление и повтор исходного; выход только если обновление не удалось. Заодно переподключение WebSocket после обновления токена.
3. **F-02, вход по `initData`.** Отправить `initData` на `POST /api/v1/auth/max`, получить JWT, разобрать `start_param` как код лекции и сразу открыть нужный экран. В MAX форма входа с паролем не показывается.

**День 2–3 (19.09, 22.09)**

4. **F-14, проверка в MAX на компьютере.** Открыть рабочее место в десктопной и веб-версии MAX: размер окна, поток событий, загрузка файлов, открытие проектора. Результат — список того, что не работает, оркестратору в тот же день.
5. **F-04, живой экран студента.** Крупный слайд, три сигнала с явным выбранным состоянием и сбросом при смене слайда, вопрос-проверка, результат после закрытия с правильным ответом и отметкой «ваш ответ». Убрать счётчик чужих ответов, перевести статус на русский, исправить «1 ответов». Уведомления не должны перекрывать кнопки (сейчас перекрывают кнопку отправки вопроса).

**День 4–6 (23–26.09)**

В презентере: сгруппировать действия вместо восьми кнопок в шапке, «Завершить» отдельно с подтверждением, сводка сигналов по слайдам и очередь вопросов с ответом в боковой панели, опрос убрать из шапки. ## Контракт с бэкендом

Зафиксирован, меняется только через оркестратора. До появления эндпоинта работай против заглушки с этой же формой ответа.

| Метод и путь | Запрос | Ответ |
|---|---|---|
| `POST /api/v1/auth/max` | `{ initData }` | `{ accessToken, expiresIn, role, personId, displayName }` |
| `GET /api/v1/me/active-session` | — | `{ sessionId, courseId, joinCode, lectureTitle, currentSlideIdx }` или 204 |
| `GET /api/v1/student/sessions/{joinCode}` | — | снапшот: `status`, `lectureTitle`, `currentSlide`, `slideCount`, `signalAggregate`, `activePoll` (в том числе закрытый, с `correctOptionIdx` и `votes`), `myVote`, `myQuestions` |
| `POST /api/v1/student/sessions/{joinCode}/signals` | `{ value, slideIdx }` | агрегат по текущему слайду |
| `POST /api/v1/student/sessions/{joinCode}/polls/{pollId}/respond` | `{ optionIdx }` | `{ accepted, myVote }`, распределение приходит только после закрытия |
| `GET /api/v1/courses/{courseId}/sessions/{sessionId}/engagement` | — | сигналы по текущему слайду, проблемные слайды, вопросы со статусами |
| `POST /api/v1/courses/{courseId}/sessions/{sessionId}/questions/{questionId}/answer` | `{ text }` | вопрос со статусом и ответом |
| `GET /api/v1/courses/{courseId}/sessions/{sessionId}/summary` | — | итог лекции |
| `GET /api/v1/student/sessions/{joinCode}/summary` | — | конспект студента |

После входа через MAX авторизация — обычный JWT в заголовке. Отдельный `participantToken` остаётся только для анонимного входа по коду.
