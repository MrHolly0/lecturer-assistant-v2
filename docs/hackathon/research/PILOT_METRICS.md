# Пилот: метрики и масштабирование

Задача M-09. Черновик от 17.09.2026, уточняется после интервью. Все целевые значения — гипотезы до базового замера.

## Формат пилота

- Один преподаватель, одна дисциплина, 2–3 сопоставимые лекции в период 01–14.10.
- Первая лекция — базовый замер без продукта: наблюдатель фиксирует вопросы и признаки непонимания, в конце — короткая проверка из 3 вопросов на бумаге или в форме.
- Следующие лекции — с продуктом, та же проверка в конце.
- После последней лекции: интервью с преподавателем (15 минут) и опрос студентов из 3 вопросов.
- Данные студентов — только MAX id и отображаемое имя; в отчёт попадают агрегаты без имён.

## Метрики

| Что проверяем | Метрика | Как считаем | Откуда данные |
|---|---|---|---|
| Вход без трения | Доля присутствующих, вошедших в лекцию | уникальные участники / присутствующие по счёту наблюдателя | событие входа + наблюдатель |
| | Время входа | от открытия ссылки до первого показа слайда, медиана и p90 | события открытия и входа |
| Обратная связь есть | Доля студентов, отправивших хотя бы один сигнал | уникальные отправившие / участники | события сигналов |
| | Сигналов и вопросов на лекцию | количество; для базовой лекции — вопросы вслух по наблюдению | события + наблюдатель |
| Преподаватель реагирует | Время реакции на всплеск «Не понимаю» | от момента, когда «Не понимаю» на слайде превысило порог, до запуска вопроса-проверки или возврата к слайду | события сигналов, слайдов, вопросов |
| | Доля всплесков с реакцией | всплески с реакцией / все всплески | те же события |
| Объяснение сработало | Доля верных ответов на вопрос-проверку | верные / ответившие по каждому вопросу | события ответов |
| | Результат итоговой проверки | средний балл по 3 вопросам в конце лекции: базовая лекция против лекций с продуктом | проверка в конце лекции |
| Участие | Доля ответивших на вопрос-проверку | ответившие / участники в момент запуска | события вопросов и ответов |
| После лекции | Открытие конспекта | студенты, открывшие конспект в течение суток / участники | событие открытия конспекта |
| Удобство преподавателю | Время подготовки лекции | от загрузки презентации до запуска, по событиям и со слов | события + интервью |
| | Готовность продолжить | ответ «да / скорее да / нет» и причина | интервью |
| Надёжность | Успешные сценарии и задержка | доля лекций без сбоя; p95 задержки от смены слайда до показа у студента | логи стенда, нагрузочный прогон |

**Честные ограничения:** 2–3 лекции и одна группа не доказывают рост успеваемости. Сигналы — самооценка студентов. Разные темы лекций по-разному сложны. Пилот проверяет, что сценарий работает и есть предварительный сигнал пользы.

## Нужные события

Сейчас в `analytics.events` пишутся только вход участника, сигнал и вопрос. Для метрик нужны ещё (задача B-17):

| Событие | Когда | Полезные поля |
|---|---|---|
| `live.session.started` / `ended` | запуск и завершение лекции | курс, лекция, число слайдов |
| `live.slide_changed` | смена слайда | номер слайда, устройство (компьютер / пульт) |
| `miniapp.opened` | открытие мини-приложения по ссылке | код лекции, платформа MAX |
| `interaction.poll_started` / `closed` | вопрос-проверка запущен / закрыт | слайд, число вариантов, правильный ответ |
| `interaction.poll_answered` | ответ студента | верно или нет |
| `qa.question_answered` | преподаватель ответил на вопрос | время с момента вопроса |
| `summary.opened` | студент или преподаватель открыл итог | роль |

Выгрузка метрик: SQL-запросы по `analytics.events` в `docs/hackathon/research/metrics.sql` (добавить вместе с B-17).

## Масштабирование

| Шаг | Что меняется | Что остаётся | Кто внедряет | Что нужно |
|---|---|---|---|---|
| 1. Второй преподаватель той же кафедры | Материалы, вопросы-проверки | Всё остальное | Преподаватель пилота рекомендует коллеге | Инструкция на 1 страницу, 15 минут на подготовку |
| 2. Другие кафедры вуза | Дисциплины (формулы, код, схемы на слайдах), размер потоков до 150–300 человек | Сценарий лекции, сигналы, вопросы, MAX | Учебно-методическое управление или центр цифрового обучения | Приглашения преподавателей через администратора вуза, нагрузочная проверка на размер потока |
| 3. Другой вуз | Развёртывание (облако или сервер вуза), роли и приглашения, правила хранения данных, связь с LMS при необходимости | Ядро продукта, бот и мини-приложение MAX | Вуз через «Цифровой вуз» / официальный канал в MAX | Договор, отдельный экземпляр или организация в общей системе (модуль `org`), поддержка |
| 4. Колледжи и дополнительное образование | Формат занятия (семинары, практики), язык интерфейса для младших студентов, данные несовершеннолетних | Сигналы понимания и вопросы-проверки | Партнёры по образовательным программам | Согласия на обработку данных, упрощённые роли |

Что уже заложено в архитектуре: модуль организаций и курсов, роли и приглашения, мультиканальность через адаптеры, нагрузочный тест на 150 студентов в одной лекции. Что добавить для шага 3: изоляция данных между вузами, администрирование вуза, мониторинг нескольких экземпляров.
