## Тестовые данные

Перед локальной проверкой задайте в `.env` значения `SEED_PASSWORD_ADMIN`, `SEED_PASSWORD_LECTURER` и `SEED_PASSWORD_ASSISTANT`, затем выполните:

```sh
docker compose run --rm seed
```

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin@lecturer-assistant.test` | закрытый канал |
| Преподаватель | `lecturer@lecturer-assistant.test` | закрытый канал |
| Ассистент | `assistant@lecturer-assistant.test` | закрытый канал |
| Студент | подтверждённый владельцем тестовый аккаунт MAX | учётные данные только утверждённым закрытым способом |

Seed использует `deploy/seed/test-lecture.pptx` и создаёт тестовый курс, презентацию, лекцию и два вопроса банка. Перед демонстрацией владелец должен убедиться, что эти данные есть именно на публичном стенде.

## Основной двухустройственный сценарий

### 1. Открыть стенд и войти преподавателем

На компьютере:

1. Откройте [https://lecturer-assistant.ru.tuna.am](https://lecturer-assistant.ru.tuna.am).
2. Войдите как `lecturer@lecturer-assistant.test`, используя пароль из закрытого канала.
3. Откройте курс `[ТЕСТ] Цифровые образовательные решения`.
4. Перейдите в «Материалы».

Ожидается: видны тестовая презентация и лекция `[ТЕСТ] Лекция 1. Обратная связь на лекции`.

### 2. Запустить лекцию

1. У тестовой лекции нажмите «Старт».
2. Запишите шестизначный код.
3. Не закрывайте презентер.

Ожидается: статус «В эфире», текущий слайд и код. В верхней панели доступны «Показ», «Инструменты», «Пауза» и «Завершить».

### 3. Подключить студента через MAX

На телефоне или во втором окне веб-MAX:

1. Откройте [@t428_hakaton_max_bot](https://max.ru/t428_hakaton_max_bot).
2. Откройте мини-приложение для текущей лекции через кнопку бота или ссылку `https://max.ru/t428_hakaton_max_bot?startapp=<код>`.
3. Не вводите локальный пароль приложения.

Ожидается:

- MAX передаёт подписанный `initData` и `start_param`;
- открывается текущая лекция;
- показан тот же слайд;
- студент появляется в списке участников преподавателя.

Важно: проверенный владельцем вход преподавателя через одноразовый код подтверждает привязку роли, но не заменяет этот студенческий шаг.

### 4. Проверить слайд и сигнал

1. На компьютере нажмите «Далее».
2. На устройстве студента убедитесь, что слайд изменился без перезагрузки.
3. Нажмите «Не понимаю».

Ожидается: номер слайда совпадает; у студента выбран сигнал, у преподавателя появляется один красный сигнал для текущего слайда.

### 5. Отправить вопрос

На устройстве студента отправьте: `Можно ещё раз объяснить этот шаг?`

Ожидается: вопрос появляется у преподавателя во вкладке «Вопросы» вместе с именем студента. Ответ и закрытие вопроса из интерфейса преподавателя в текущую проверку не входят.

### 6. Запустить вопрос из банка

На компьютере:

1. Нажмите «Опрос».
2. Откройте вкладку «Из банка».
3. Выберите `[ТЕСТ] Что видит преподаватель после закрытия быстрого опроса?`.

На устройстве студента выберите «Распределение ответов студентов».

Ожидается: студент видит «Ваш ответ сохранён» без распределения; у преподавателя отображается один ответ.

На компьютере нажмите «Закрыть и показать результат». Правильный вариант уже задан в банке.

Ожидается: преподаватель и студент видят распределение и правильный вариант; студент видит собственный ответ.

### 7. Пауза и завершение

1. Нажмите «Пауза» и проверьте, что действия студента недоступны.
2. Продолжите лекцию.
3. Нажмите «Завершить» и подтвердите.

Ожидается: статус `ENDED`; новые сигналы, вопросы и ответы не принимаются. Преподаватель видит экран «Лекция завершена» с длительностью, числом участников и сигналов, числом вопросов без ответа, проблемными слайдами и результатами проверок.

## Веб-резерв без MAX

Если MAX недоступен, на втором устройстве вручную откройте:

```text
https://lecturer-assistant.ru.tuna.am/#/s/<шестизначный код>
```

Введите имя `Жюри Студент` и повторите шаги 4–7. Этот путь проверяет ядро и интерфейс, но не подтверждает интеграцию MAX.

## Отдельный протокол полного студенческого сценария MAX

Прогон считается подтверждённым только после заполнения всех полей и сохранения доказательства вне репозитория без секретов.

| Поле протокола | Что записать |
|---|---|
| Дата и точное московское время | Заполняет ведущий прогона |
| Полный commit hash | Версия кода стенда |
| Публичный адрес стенда | Финальный URL из формы |
| Бот и способ запуска | `@t428_hakaton_max_bot`, `https://max.ru/t428_hakaton_max_bot?startapp=<код>` |
| Устройство и версия MAX преподавателя | Desktop/web, ОС и версия |
| Устройство и версия MAX студента | Mobile/web, ОС и версия |
| Учётные роли | Только публичные логины или обезличенные идентификаторы |
| Пройденные шаги | Вход, слайд, сигнал, вопрос, открытый/закрытый опрос, завершение |
| Фактический результат | PASS либо дефект на конкретном шаге |
| Доказательство | Ссылка на видео/скриншоты в разрешённом хранилище |
| Кто проверил | Имя ответственного внутри команды |

Не помещать в протокол пароли, токены, `initData`, cookies, webhook secret или содержимое серверного `.env`.

## Что подтверждает только владелец

Перед отправкой владелец передаёт команде документации:

1. точное время дедлайна 30.09 по Москве и полный перечень полей формы;
2. финальные публичные адреса: репозиторий, стенд, OpenAPI и при необходимости видео; бот уже подтверждён как `@t428_hakaton_max_bot`;
3. какие публичные тестовые логины разрешено указать в форме;
4. каким закрытым каналом жюри получает пароли и доступ к тестовому MAX-аккаунту;
5. дату, устройство и результат уже выполненного входа преподавателя через код;
6. ссылку на отдельный протокол полного студенческого прогона после его выполнения.
