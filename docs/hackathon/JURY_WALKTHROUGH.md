# Проверка Lecturer Assistant для жюри

Это **инструкция по действиям**, а не второй бриф презентации и не отчёт о готовности. Команда уже провела живую лекцию на публичном стенде: преподаватель работал с занятием, студентка участвовала через мини-приложение MAX. При совместном тесте нашли и исправили дефекты повторного входа, дублирования студента и синхронизации; после повторной проверки владелец сообщил, что сценарий работает. Сохранённой таблицы с PASS для каждого шага нет.

Для самостоятельной проверки жюри нужны компьютер преподавателя с браузером и телефон со своим аккаунтом MAX. На публичном стенде используются тестовые данные. Создавать администратора не требуется.

## Адреса и доступ

- Стенд: `https://lecturer-assistant.ru.tuna.am/`.
- Бот и мини-приложение: `https://max.ru/t428_hakaton_max_bot`.
- Преподаватель: `lecturer@lecturer-assistant.test`; пароль указан на первом слайде закрытого PDF, переданного организаторам.
- Студент: собственный аккаунт MAX проверяющего; отдельного пароля приложения нет.
- Исходники: `https://github.com/MrHolly0/lecturer-assistant-v2`, полный commit указан на первом слайде; сверить через `git rev-parse HEAD` в выбранной версии.
- API: `https://lecturer-assistant.ru.tuna.am/api/v1`; [OpenAPI](../../openapi/lecturer-assistant-v2.yaml) и [DATA-API.yaml](../../DATA-API.yaml).

Тестовый курс — `[ТЕСТ] Цифровые образовательные решения`, лекция — `[ТЕСТ] Лекция 1. Обратная связь на лекции`. Код занятия появляется при каждом запуске; заранее известного постоянного кода нет.

## Основной сценарий на двух устройствах

1. **Вход и запуск.** На ПК открыть стенд, войти преподавателем, выбрать тестовый курс и лекцию, нажать «Запустить». Ожидается презентер с первым слайдом и кодом занятия. Проектор открывается отдельно от окна управления.
2. **Студент в MAX.** На телефоне открыть бота, запустить мини-приложение, подключиться по коду. Ожидается тот же текущий слайд и студент в списке участников преподавателя. Локальный пароль сайта студенту не нужен.
3. **Смена слайда и сигнал.** Преподавателю перейти на следующий слайд. У студента слайд меняется без перезагрузки. Студент отправляет «Не понимаю»; преподаватель видит сигнал для текущего слайда.
4. **Вопрос и ответ.** Студент задаёт вопрос. Преподаватель видит его, отвечает лично; студент получает ответ. Если подключены два студента, можно отдельно проверить публичный ответ всей аудитории.
5. **Проверка понимания.** Преподаватель запускает вопрос из банка или быстрый вопрос. Студент отвечает; до закрытия видит только сохранение своего ответа. После закрытия обе стороны видят результат и правильный вариант. В тестовом банке есть вопрос `[ТЕСТ] Что видит преподаватель после закрытия быстрого опроса?`.
6. **Пауза и завершение.** Преподаватель ставит лекцию на паузу и продолжает её. На паузе действия блокируются, активное время не растёт. После «Завершить» новые действия закрыты, проектор закрывается или показывает выход, а преподаватель открывает итог.
7. **История и аналитика.** Преподаватель возвращается в курс, открывает завершённую лекцию, результаты проверки и аналитику по группам и студентам. Эти данные показывают наблюдаемые взаимодействия; продукт не определяет списывание.
8. **Повторное открытие MAX.** Студент сворачивает мини-приложение и открывает его снова. Оно должно вернуться к той же личности и актуальному состоянию занятия без нового подключения или дублирования студента.

Если MAX временно недоступен, на втором устройстве можно открыть веб-резерв `https://lecturer-assistant.ru.tuna.am/#/s/<код>`. Он позволяет проверить ядро сценария, но **не заменяет проверку внутри MAX**.

## Проверка API и воспроизводимости

`POST /api/v1/auth/login` с тестовым логином и паролем преподавателя возвращает access token; следующие запросы перечислены в `DATA-API.yaml`. На обновлённом стенде 27.09 прошли 8/8 API-проверок. Точный YAML-шаблон организаторы не предоставили, поэтому машинные имена полей в `DATA-API.yaml` предварительные.

Для локального запуска использовать [README](../../README.md), `docker-compose.yml`, `.env.example` и seed-команду `docker compose run --rm seed`. Рабочий токен публичного бота не нужен для проверки уже развёрнутого стенда; для независимого запуска MAX-бота потребуется отдельный токен и настройка своего бота.
