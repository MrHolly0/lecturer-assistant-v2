# Промт: упаковка и стенд

Скопировать целиком в начало работы разработчику или агенту. Обновлено 18.09.2026.

---

Ты отвечаешь за то, чтобы проект `lecturer-assistant-v2` запускался одной командой, собирался за 5 минут, работал на стенде по HTTPS и проходил проверку жюри по документации. Хакатон MAX, отправка 30.09.2026, заморозка кода 29.09.

## Контекст

Модульный монолит Spring Boot (Java 21) в `core/`, React/Vite в `web/`, конвертер презентаций на Python + LibreOffice в `deploy/converter/`, адаптеры мессенджеров — Node-процессы в `adapters/`, PostgreSQL. Параллельно работают бэкенд (логика и API) и фронтенд (интерфейс).

Обязательно прочитать до начала:

- `docs/hackathon/research/PACKAGING_GAPS.md` — полный разбор пробелов с файлами и строками, замер сборки.
- `docs/hackathon/PROJECT_BRIEF.md`, разделы 1, 9 и 11 — требования задания, тестовый стенд, готовность к сдаче.
- `docs/hackathon/research/MAX_API_NOTES.md`, разделы 1 и 4 — требования MAX к вебхуку и публикации.

## Требования, которые проверит жюри

- `docker compose up` поднимает все локальные компоненты продукта, включая веб и адаптеры.
- Сборка образов — не дольше 5 минут без учёта загрузки базовых образов.
- В репозитории: Dockerfile, compose, `.dockerignore`, `.env.example` без секретов, lock-файлы.
- README описывает: назначение, сценарий, архитектуру, запуск, переменные окружения, порты, зависимости, интеграции, данные и тестовые данные, шаги проверки и ожидаемые результаты, ограничения, остановку и повторный запуск.
- Для своего API: OpenAPI, тестовые учётные записи по ролям, тестовые данные, `DATA-API.yaml`.
- Стенд доступен всё время оценки, с 30.09 по 14.10.

## Границы

Твои файлы: `core/Dockerfile`, `web/Dockerfile`, `deploy/`, `docker-compose*.yml`, `.dockerignore`, `.env.example`, `README.md`, скрипты тестовых данных, `DATA-API.yaml`. Dockerfile для `adapters/max` — тоже твой, сам адаптер пишет бэкенд.

Не трогаешь: код в `core/src`, `web/src`, `adapters/*/` (кроме Dockerfile), миграции, `openapi/lecturer-assistant-v2.yaml` — это зона бэкенда. Нужны изменения в коде ради упаковки — пишешь оркестратору.

## Правила

- База — `v2/phase-5-web-student-channel`. Ветка на задачу: `feat/P-01-build-time`. Коммит начинается с номера задачи.
- Секреты только в `.env` на сервере и в менеджере паролей. В репозиторий не попадает ни токен бота, ни `JWT_SECRET`, ни ключ адаптера, ни пароль базы стенда.
- Каждое изменение сборки подтверждается замером: условия, время, что было в кэше.
- На машине разработчика заняты порты 80, 443, 3000, 5432, 8080–8082, 6379 другим проектом. Локально поднимай стек на других портах через переменные.

## Очередь работ

**P-01. Время сборки** — начать первым, самая долгая задача.
Сейчас полная сборка идёт около 31,5 минуты при нормативе 5. В `deploy/converter/Dockerfile:3–8` метапакет `libreoffice` тянет 206 пакетов и 153 МБ — это 31 минута из 31,5. Заменить на `libreoffice-impress` с фиксацией версий, проверить, что конвертация PPTX и PDF работает. В `core/Dockerfile:3–6` вынести `pom.xml` в отдельный слой с `mvn dependency:go-offline`, исключить тестовые зависимости из сборки образа. Готово, когда холодная сборка с прогретыми базовыми образами укладывается в 5 минут и замер записан.

**P-02. Запуск одной командой.**
Адаптеры в compose со своими Dockerfile. Пробросить `CHANNEL_INTERNAL_API_KEY` в `core` (сейчас молча берётся дефолт, напечатанный в четырёх файлах репозитория). Параметризовать порт Postgres. `restart:` для всех сервисов, healthcheck для `core`, `web`, `converter`. Готово, когда на чистом клоне `docker compose up --build` поднимает всё и продукт открывается.

**P-03. Переменные окружения.**
Дописать в `.env.example` одиннадцать переменных из `application.yml`, которых там нет, в том числе `SLIDE_IMAGE_URL_SECRET`, `MAX_BOT_TOKEN`, `MAX_INIT_DATA_MAX_AGE`. Убрать мёртвую `CLOUDFLARED_TOKEN`. У каждой — комментарий, что это и откуда взять.

**P-04. Стенд.**
VPS, домен, Caddy с HTTPS и сертификатом доверенного удостоверяющего центра (MAX не принимает самоподписанные), `docker-compose.prod.yml`, `REQUIRE_STRONG_JWT_SECRET=true`, ежедневная резервная копия базы, простой мониторинг доступности. Готово к 22.09: мини-приложение и вебхук доступны по HTTPS, перезапуск сервера не ломает стенд. Доступ к серверу и домену даёт владелец проекта.

**P-05. Тестовые данные.**
Скрипт наполнения: тестовые учётки преподавателя, ассистента и администратора; курс; лекция с загруженной презентацией; заготовленные вопросы-проверки. Запускается одной командой после `up`. Данные явно помечены как тестовые.

**P-06. `DATA-API.yaml`.**
Схема и версия — у организаторов, уточняет владелец. До ответа подготовить черновик по перечню полей из задания.

**P-07. README.**
Все двенадцать разделов требования. Текущий README — 32 строки «быстрого старта фазы 0», переписать целиком. Отдельно: время сборки с условиями замера, известные ограничения, какие данные тестовые.

**P-08. Проверка «глазами жюри».**
29.09 человек, не участвовавший в разработке, проходит запуск и сценарий только по README на чистой машине. Все места, где он застрял, исправляются до отправки.
