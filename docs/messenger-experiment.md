# Эксперимент: MAX, Telegram и VK

Ветка `feature/messenger-experiment`. Вход Telegram/VK выключен по умолчанию;
MAX и обычный браузерный вход сохраняются. Это отдельный эксперимент для проверки
пользовательских сценариев, не объявление промышленной готовности новых каналов.

## Настройка

1. Нужен HTTPS origin установки. Для Telegram зарегистрируйте бот и Mini App
   через BotFather, укажите origin приложения для кнопки меню. Для VK создайте
   Mini App с этим же адресом и разрешёнными адресами запуска.
2. В приватном окружении API задайте `EXPERIMENTAL_MESSENGER_LOGIN=true`,
   `TELEGRAM_BOT_TOKEN` и/или `VK_APP_ID`, `VK_APP_SECRET`. Не передавайте эти
   секреты веб-приложению. Compose и Kubernetes передают их только серверной части.
3. Откройте приложение из официального клиента. Запуск напрямую из браузера
   не является входом Telegram/VK: сервер требует свежие подписанные параметры.
4. Для существующего аккаунта откройте «Ещё → Другие мессенджеры» и получите
   одноразовый код. В новом канале выберите подключение аккаунта. ФИО и совпадение
   почты не служат основанием для автоматического объединения профилей.

Telegram Mini App работает через кнопку меню без запуска legacy long-poll адаптера.
Старый `adapters/telegram` остаётся отдельным чатовым сценарием; он не требуется
для Mini App и пока не заменяет все функции MAX по отправке слайдов в личный чат.
VK получает подтверждённый числовой ID; личное ФИО студент уточняет средствами
приложения. OAuth-профиль VK и чатовый бот не добавлены.

## Кабинет и участие

Обычный вход студента открывает текущие занятия его групп и историю с пагинацией.
Совпадение групп между курсами использует структурный ключ формата учреждения,
а не свободное название. Запрет доступа к курсу исключает его занятия из списка.
Студент может покинуть занятие, вернуться и выбрать другое; старое незавершённое
занятие не перехватывает навигацию. Повторный вход сохраняет запись участника.
Поздние квитанции и команды после выхода не восстанавливают участие; возобновление
идёт через явный join. На возврате старый токен участия заменяется новым.

История гостя без аккаунта не становится историей другого человека по совпадению
имени. Идентификация гостя и его локальное возвращение имеют прежние ограничения
хранилища WebView. Постоянный публичный тег не подтверждает личность студента.

## Проверка и границы

Сервер проверяет HMAC, срок запуска, app ID для VK, положительный ID пользователя,
дубли параметров и конфликты привязок. Cookie обновления раздельные для браузера,
MAX, Telegram и VK. Параметры запуска удаляются из URL; веб access log выключен,
Referrer-Policy=no-referrer. Внешний reverse proxy учреждения тоже должен исключать
launch query из журналов и аналитики.

Локальные тесты используют подписанные фикстуры и изолированную PostgreSQL;
браузерные проверки используют подменённые ответы API. Реальные Telegram/VK
клиенты и зарегистрированные боты/приложения этой установкой пока не проверены.
Нужны проверки cookies в WebView, повторного открытия, истёкшей сессии и действий
на настоящем занятии с двумя разными мессенджерами.

Первичные протоколы:
- https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app
- https://github.com/VKCOM/vk-apps-launch-params

Эксперимент включает стабильный кандидат выпуска с центром обновлений, кабинетом
и форматом групп. Повторный подписанный вход после отклонённой сессии отделён от
явного выхода пользователя; устаревшие launch-данные предлагают переоткрыть Mini App.
