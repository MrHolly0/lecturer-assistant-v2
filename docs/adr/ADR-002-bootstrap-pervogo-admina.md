# ADR-002: Bootstrap первого администратора

Контекст: регистрация по ТЗ идёт через приглашения, но в пустой установке ещё нет администратора, который может создать первое приглашение.

Решение: оператор установки задаёт случайный `ADMIN_SETUP_TOKEN` и один раз вызывает `POST /api/v1/auth/bootstrap-admin` с заголовком `X-Admin-Setup-Token`. Без настроенного секрета или с неверным заголовком endpoint возвращает `404`. После создания администратора endpoint возвращает `409`; секрет удаляют из окружения и пересоздают контейнер core, чтобы новое окружение вступило в силу.

Почему: это позволяет развернуть отдельную установку без секретов в репозитории и без ручного SQL, но не оставляет публичную саморегистрацию администратора.

Ограничение проверяет наличие роли `ADMIN`, а не любой записи в `iam.persons`: студент может войти через MAX раньше оператора. Транзакционная блокировка исключает одновременное создание двух первых администраторов.

Следующие сотрудники регистрируются по приглашению администратора. Студент в MAX может войти без приглашения и получает роль `STUDENT`.

JWT/refresh и роли применяются к bootstrap-admin так же, как к обычной регистрации.

Решение локально для фазы 1 и не меняет технологический стек §3.1.
