# Предупреждения и порядок действий

Для одной ВМ применимы предупреждения из `deploy/appliance/render.py`. Доставку настраивает
учреждение через свой Alertmanager (`monitoring.alertmanagerUrl`); до подключения получателя
правила можно проверить в Prometheus `/alerts`. Метрики доступны только во внутренней сети.

| Сигнал | Что проверить и сделать |
|---|---|
| BackupStale / BackupFailed | Доступность независимого хранилища, место, сертификат получателя, ответственного и журнал сервиса `backup`. Проверить последний завершённый `.cms`, не считать `.partial` копией. После исправления выполнить копию и контрольное восстановление на новой установке. |
| OperationsCollectorFailed / ScrapeFailed | Доступность компонента, внутренние адреса/порты и права наблюдения. Отсутствующие метрики не означают отсутствие аварии. Сначала восстановить наблюдение, затем оценить очередь/диск. |
| PodPending / MemoryBudgetNearFull | Причины Pending, ResourceQuota и реальные лимиты Docker/ВМ. Не поднимать максимумы реплик без пересчёта всего бюджета, включая последовательное обновление и платформу. |
| PodOOM | Предыдущий статус и рестарты, working set, JVM/Node/Go параметры, активные конвертации и число соединений. Сначала остановить рост нагрузки; перезапуск без устранения причины может вызвать цикл аварий. |
| DiskReserveLow | Отдельно место материалов, PostgreSQL/WAL, RabbitMQ, рабочие файлы конвертера и копии. Не удалять файлы PostgreSQL/WAL или учебные материалы вручную. При необходимости временно ограничить импорт, увеличить файловую систему по процедуре учреждения и проверить целостность. |
| PostgresLockQueue | Активные транзакции и возраст ожиданий, пул API и служебный пул проверок доступа. Не увеличивать количество API-подов выше бюджета соединений; это может усилить очередь. |
| ImportStalled / DeadJobs | Причину последней ошибки и текущий lease. Исправить недоступный сервис/неподходящий документ/квоту, затем выполнить контролируемый повтор. Не очищать outbox, чтобы скрыть предупреждение. |
| UpdateNeedsAttention | Последний этап обновления, журнал проверки и фактически запущенные digest. Зафиксировать состояние и действовать по плану восстановления. Не откатывать БД автоматически и не снимать fencing вручную. |
| HttpFallbackStorm | Размеры снимков, историю/рисование, состояние SSE, частоту инвалидирования и RPC. Проверить, что студенты получают compact-снимки и подгружают историю только при смене её scoped revision. |

Отдельная ВМ остаётся единой точкой отказа. Для её потери нужны рабочая внешняя копия,
доступный закрытый ключ восстановления и проверенная процедура запуска на новой ВМ.
Ресурсы Kubernetes внутри Docker не увеличивают физическую память, CPU или пропускную
способность сети. Предел массового видео проверяется на целевом оборудовании.

Образы выпуска проходят сканирование обеих архитектур и получают SBOM. Исправимые HIGH/CRITICAL
блокируют подпись каталога. Исключение требует отдельного рассмотрения достижимости, срока
и ответственного; молчаливое отключение проверки или общий ignore для всех CVE недопустимы.
Для ещё не исправленных upstream-уязвимостей сохраняется отчёт и решение о допустимости
эксплуатации. Зависимости инструментов сборки также требуют сопровождения, даже если они
не входят в исполняемый frontend.
