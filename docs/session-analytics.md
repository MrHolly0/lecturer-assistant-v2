# Аналитика завершённого занятия

Итог открывается после завершения занятия и из истории курса. В обоих случаях
используется `PresenterSessionSummary`. Все действия внутри итога доступны только
для чтения: просмотр слайда, раскрытие вопроса, фильтры и загрузка следующих вопросов.

## Что показываем

- «Требует внимания»: слайды с красными сигналами, проверки с неверными ответами,
  вопросы со статусом `OPEN`. Кнопки переводят к соответствующему разделу внутри
  страницы, сохраняя маршрут HashRouter.
- Распределение сигналов и взвешенная доля верных ответов; отдельные результаты
  проверок, история вопросов и сравнение учебных групп.
- Слайды с затруднениями открываются из презентации, закреплённой за занятием
  (`session.deckId`). Просмотр не переключает слайд в эфире. Ошибки загрузки
  презентации и самого изображения имеют повторную попытку.

## Смысл чисел

Сигнал — последний сохранённый выбор одного участника на одном слайде. Распределение
сигналов не является долей студентов или количеством всех нажатий. `problemSlides`
содержит только слайды с красными сигналами; из этого набора нельзя восстановить
карту активности всех слайдов.

Правильность считается как сумма верных ответов, делённая на сумму ответов в
закрытых проверках с допустимым `correctOptionIdx`. Проценты отдельных проверок
не усредняются. Например, 8/10 и 0/1 дают 8/11 ≈ 73%. Проверки без правильного
варианта и незакрытые проверки исключаются из оценки; их ответы показаны отдельно.
Отсутствие оценённых ответов отображается как отсутствие данных, а измеренные
0 верных из 1 — как 0%.

`participantCount` обозначает подключения, поскольку каналы одного человека могут
иметь отдельные записи. Разбивка по группам использует группы, закреплённые за
занятием. Общие числа могут включать подключения без группы.

История вопросов запрашивается страницами по 50 через staff API с фильтрами
`OPEN`, `ANSWERED`, `DISMISSED`. Скрытые вопросы не считаются отвеченными.
Видимость сохранённого ответа (`AUTHOR` / `SESSION`) подписана явно. При сбое
истории доступны открытые вопросы из итоговой сводки; неизвестные количества
остальных статусов не подменяются нулями.

## Проверка изменений

- `npm test`: расчёт с весами ответов, отсутствие данных, измеренный ноль,
  недопустимые индексы и незакрытые проверки.
- Локальная браузерная приёмка на синтетическом завершённом занятии: 36 сохранённых
  сигналов, три проверки, 55 вопросов, пагинация, ошибки API/изображения и повторные
  попытки, сохранение маршрута и возврат фокуса.
- Светлая/тёмная тема, ширины 360–2048 px. Семантический жёлтый цвет сохраняется
  в обеих темах. Снимки и протокол находятся в игнорируемой папке
  `output/playwright/session-analytics-20261018/`.

Проверка адаптива в Chromium не заменяет проверку на физическом телефоне и в MAX.
