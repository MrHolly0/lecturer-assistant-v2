# Ресурсы и устойчивость стенда

Параметры ниже — начальный эксплуатационный бюджет. Они ограничивают последствия
перегрузки, но не подтверждают число одновременных занятий. Слайды, импорт и
демонстрацию экрана нужно измерять отдельными сценариями.

## Контейнеры

Compose применяет `mem_limit`, `cpus`, `pids_limit` непосредственно к контейнерам.
Логи используют драйвер `local`: три файла по 10 МБ на сервис. Лимиты памяти —
верхние границы, не заранее выделенная память.

| Сервис | Память по умолчанию | CPU | PID |
|---|---:|---:|---:|
| core | 2 ГиБ | 2 | 256 |
| PostgreSQL | 768 МиБ | 2 | 128 |
| converter | 1536 МиБ | 1 | 128 |
| Caddy | 256 МиБ | 1 | 128 |
| web | 128 МиБ | 0,5 | 64 |
| MAX adapter | 256 МиБ | 0,5 | 64 |
| backup | 256 МиБ | 0,5 | 64 |

Для полного стека с импортом начните с 8 ГБ RAM, оставляя запас ОС и Docker.
Прежняя рекомендация 4 ГБ не покрывает одновременное достижение этих бюджетов.
Меняйте значения через `.env`, сохраняя запас для реальных тяжёлых презентаций.

Java получает heap до 60% лимита контейнера. Остальное нужно metaspace, code cache,
direct buffers, стекам и native allocations. `CORE_JAVA_TOOL_OPTIONS` заменяет весь
набор flags. При увеличении CPU согласуйте `-XX:ActiveProcessorCount`; при изменении
RAM проверьте heap, RSS, GC и отсутствие OOM на импорте/видео, а не только `/health`.
Caddy получает мягкий `GOMEMLIMIT=160MiB` и `GODEBUG=disablethp=1`; это не жёсткий
лимит RSS и не обещание конкретной экономии памяти.
`CADDY_GO_MAX_PROCS=1` согласует Go scheduler с его CPU-бюджетом; при изменении
CPU измените это значение. Nginx подбирает число workers по cgroup-лимиту.

Hikari: до 16 соединений на core, минимум 2, ожидание 3 с. PostgreSQL: максимум 80
соединений. Сумма пулов всех процессов плюс backup/maintenance должна оставаться
ниже лимита БД с резервом. Application sessions имеют statement timeout 30 с,
lock timeout 5 с и idle transaction timeout 60 с. Эти настройки не применяются
к backup session: её длительная блокировка нужна согласованной паре DB+blob.

## Чтения, команды и повторы

Студент получает SSE, преподаватель — STOMP/WebSocket. HTTP остаётся резервом.
Клиент не копит параллельные запросы снимка; повторы имеют deadline, нарастающую
задержку и jitter. `Retry-After` задаёт минимальную задержку, включая HTTP-date.
Здоровое соединение не пересоздаётся при обычном возврате в окно.

Caddy исключает пути SSE из gzip и ставит `Cache-Control: no-cache, no-transform`.
На используемом образе 2.8 сжатие задерживало завершённые события; проверка с
обычными заголовками клиента должна проходить через прокси, а не только напрямую
через core. Остальные ответы и статические файлы продолжают сжиматься.

У STOMP входящая и исходящая очереди ограничены 256 задачами каждая, с 2–4
потоками на направление. Входящий кадр — до 64 КиБ; команды по STOMP запрещены,
изменения идут через HTTP. У медленного сокета send buffer ограничен 256 КиБ,
время отправки — 5 с. При насыщении обновление может не дойти; клиент сверяется
с HTTP, поэтому это не гарантированная доставка каждого промежуточного события.

Снимок занятия до 256 КиБ отправляется готовыми JSON-байтами. Для более крупного
снимка сервер посылает `session.invalidate` с `sessionId`, `version` и `eventType`;
объект с большими рисунками в очередь брокера не попадает. Новый веб-клиент тихо
читает актуальный снимок по HTTP, объединяет уведомления и не блокирует кнопки
при здоровом соединении. Между дополнительными чтениями — 1–1,25 с с разбросом;
если ответ отстал, допускается один повтор, затем обычное резервное чтение.
Этот wire-контракт требует совместного обновления core и веба.

Квоты API различают пользователя/participant token и дорогую аналитику. Есть
границы числа ключей, времени простоя и одновременно исполняемых запросов.
Квоты и семафоры действуют в одном процессе: это не глобальный распределённый RPS.
JSON ограничен 4 МиБ на запрос и общим бюджетом 64 МиБ тел до разбора Jackson;
multipart и медиапотоки имеют свои ограничения.

`Idempotency-Key` сохраняет результат поддерживаемой команды на 24 часа в одной
транзакции с бизнес-изменением. Ключ ограничен actor + operation/route; другой
payload с тем же ключом получает 409. Права проверяются и при повторе. Используйте
один ключ на логическую попытку формы до подтверждённого ответа. Не повторяйте
автоматически произвольный POST без такого контракта.

Для смены слайда и сохранения рисунков новый клиент передаёт `expectedVersion`.
Конфликт другого окна требует сверки состояния; локальный рисунок сохраняется
для явного решения пользователя. Старые клиенты без поля сохраняют совместимость.

## Фоновые задачи

Очередь импорта хранится в PostgreSQL. Worker атомарно получает claim с owner,
lease и token, продлевает lease, а запись результатов проверяет актуальность claim.
Просроченные задания возвращаются в очередь с ограниченным числом попыток;
отложенные повторы учитывают Retry-After. Очередь ограничена 128 заданиями.

`CONTENT_WORKER_ENABLED=false` отключает исполнение импортов в данном core.
Два процесса могут разделять импорт через БД, если используют один blob storage
и доступный конвертер. Это не делает realtime всего приложения распределённым.
Конвертер допускает два преобразования, один LibreOffice и до 16 HTTP workers.
При насыщении отвечает 503; задачи ждут в durable queue, а не в бесконечной памяти.

Перед обновлением со старого протокола импортов нужно дождаться завершения
PENDING/RUNNING и остановить старых workers. Старый процесс не понимает fencing
нового claim; смешанный запуск старого и нового worker не поддерживается.

Outbox уже использует `SKIP LOCKED`, lease, attempt token и DLQ. Интервалы ошибок
имеют jitter и потолок. MAX adapter дополнительно резервирует общий provider slot
в БД; 429 устанавливает общий cooldown. Доставка внешнему провайдеру остаётся
at least once: потерянное подтверждение после успешной отправки допускает дубль.
Идемпотентность нашего API не превращает внешний API в exactly once.

Независимые blob writers берут shared advisory lock. Backup берёт exclusive lock:
файлы и база остаются согласованы, без глобальной сериализации всех конвертаций.

## Метрики и проверка

Внутренний `GET /internal/v1/operations/metrics` требует `X-Internal-Api-Key`.
Caddy не публикует этот маршрут. Он отдаёт разрешённые метрики текущего процесса:
JVM/GC, Hikari, API admission, SSE очереди/клиенты, read caches и media budgets.
Идентификаторы пользователей, занятий и токены в labels не входят.

Пример проверки из контейнера, без публикации ключа в адресе или командной истории:

```sh
docker compose exec -T core sh -c 'curl -fsS -H "X-Internal-Api-Key: $CHANNEL_INTERNAL_API_KEY" http://127.0.0.1:8080/internal/v1/operations/metrics'
```

Проверяйте: OOM/restarts, постоянно заполненные очереди, отказы admission,
Hikari pending/timeout, рост GC, просроченные jobs/outbox и возраст backup.
429/503 при исчерпанном бюджете — управляемый отказ, а не успех нагрузочного теста.
Успех считают относительно всех запланированных клиентов, включая не подключившихся.

## Границы масштабирования

Simple STOMP broker, SSE subscribers, signalling и видеобуферы пока локальны core.
Для нескольких realtime replicas нужны согласованная маршрутизация и обмен
обновлениями между процессами; одного `--scale core=2` недостаточно.
Число media rooms, viewers и байтовые бюджеты настраиваются отдельно. Увеличение
rooms без запаса памяти и пропускной способности не увеличивает реальную ёмкость.

Read side отделяется внутри текущего монолита и PostgreSQL. Ревизии чтения и
перестроение моделей должны охватывать все изменения; журнал аналитики не является
полным event-sourcing store. Отдельный брокер или база требуют измеримой причины.
Итоги завершённых занятий сохраняются в PostgreSQL и перестраиваются при смене
ревизии исходных данных. Права преподавателя проверяются перед каждым чтением.
Контракт инвалидации, ограничения размера и принудительное перестроение:
[модели чтения](read-models.md).

Один Mac, один PostgreSQL и один туннель остаются единичными точками отказа.
`restart: unless-stopped`, health checks и backup не являются HA. Храните проверенную
копию на независимом носителе/сервере и выполняйте restore drill в отдельном проекте.
