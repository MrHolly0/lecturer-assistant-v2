# Проектор, демонстрация окна и приватный пульт

Основной сценарий остаётся в сайте и MAX. Преподавателю не нужен личный телефон
для управления очным показом. Настройка проектора доступна сотрудникам через «Ещё»
или «Инструменты» живого занятия; студенческое меню её не содержит.

## HDMI без установки

1. Подключить проектор. Открыть «Настройка проектора» в настольном браузере.
   Из MAX внешний браузер открывается явным нажатием. При необходимости вход в аккаунт
   возвращает именно к начатой настройке; обычная главная сайта сохраняет прежний вход.
2. Включить независимый рабочий стол по инструкции своей ОС. Windows 10/11: Win+P →
   «Расширить». Мастер содержит разные пути macOS 13+, Monterey и 10.15/11.
3. Разрешить браузеру управление окнами. Выбрать целевой экран явно; рабочий экран
   недоступен для выбора. Номер, имя или признак primary не доказывают, что это проектор.
4. Проверить нейтральный код **на физическом проекторе** и подтвердить его в мастере.
   Только затем открывается публичный материал. На тестовом экране есть отдельная
   кнопка полного экрана: браузер может требовать ещё одно нажатие.
5. Перейти к занятию. Слайды и рисунки синхронизируются публичным состоянием.

Закрытие обучения пропускает только объяснения. Разрешения, выбор экрана и физическая
проверка обязательны. Отказ в разрешении, отсутствие API, отсутствие независимого
экрана, неверное размещение и блокировка popup — разные состояния. После изменения
экранов, переноса управляющего окна, потери разрешения или связи подтверждение снимается,
а публичное окно возвращается к нейтральному содержимому.

Браузер сам не переводит HDMI из Duplicate в Extend и не определяет «пустоту» экрана.
Показ не объявляется успешно настроенным только потому, что window.open вернул объект.
Перед возвратом Duplicate нужно закрыть приватные окна; мастер закрывает свой проектор,
пульт и накрывает рабочую страницу нейтральной заставкой с обратной инструкцией.
Изменение режима ОС остаётся явным действием человека.

## Демонстрация приложения

«Показать окно» запрашивает отдельное окно приложения или вкладку. Перед отправкой
преподаватель видит настоящий предпросмотр и подтверждает отсутствие служебных данных.
Целый рабочий стол не разрешён: браузерный пульт ещё нельзя надёжно исключить из такого
захвата на всех ОС. Неизвестный тип захвата также отклоняется до публикации.

Пульт содержит цветные сигналы, новые/отвеченные/скрытые текстовые вопросы, личный
ответ и отдельное подтверждение публикации без имени. При сворачивании сохраняются
вопрос и черновик. Новые вопросы меняют счётчик, но сами не раскрывают окно. В Chrome
доступно окно поверх приложений через Document Picture-in-Picture; в других браузерах
используется отдельное окно без обещания always-on-top. Самостоятельное сворачивание
исходного приложения может ограничить обновление его захвата: это проверяется на ОС.

Пауза занятия, остановка демонстрации, закрытие физического проектора и завершение
занятия — разные действия. Потеря прав, lease или источника прекращает передачу;
старые кадры не должны оставаться под видом живой демонстрации. Публичная сцена никогда
не запрашивает преподавательские вопросы, черновики, заметки или правильные ответы.

## Медиатранспорт и эксплуатационные границы

Первый транспорт — WebRTC с video-only потоком, SDP в ограниченной памяти одного
экземпляра core и короткими lease. Звук не запрашивается. ICE-сервер учреждения можно
задать `app.projection.ice-urls`, `ice-username`, `ice-credential`; по умолчанию внешний
STUN/TURN-провайдер не используется. Сетевые адреса в SDP и TURN credentials нельзя
логировать или сохранять как аналитику. Для TURN нужны отдельные ограниченные учётные
данные, квоты и безопасная ротация; это не пароль преподавателя.

Если WebRTC не подключился, включается передача обновляемого JPEG-изображения через
тот же HTTPS: максимум 960×540, до двух кадров в секунду, без звука. На сервере
хранится только последний кадр текущего показа, не более 256 KiB, в памяти и не дольше
четырёх секунд. Доступ проверяется так же, как для видеосигналинга. Пауза, остановка,
истечение lease или потеря доступа убирают кадр; старое изображение не выдаётся за
продолжающийся показ. Для локального браузерного проектора тот же кадр идёт только
через случайный канал проверенной попытки. Такой режим подходит для приложений и
кода, но не заменяет плавное видео.

Перед промышленным использованием нужно измерить число одновременных получателей,
исходящий канал и CPU преподавательского ПК. P2P создаёт отдельный поток на зрителя;
это не SFU и не доказательство ёмкости 10×150. HTTP-сигналинг не переживает перезапуск
core: клиенты прекращают старое соединение и переподключаются. Многорепличное размещение
потребует общего signal/media слоя или sticky routing с явной семантикой отказа.

В браузере проектор получает только публичный медиаканал конкретной случайной попытки,
а не канал по одному коду лекции. В отдельном native WebView используется ограниченный
read-only grant в URL fragment и `X-Projection-View-Token` при запросах. Staff JWT и
device credential в URL не передаются. Grant не разрешает публикацию, команды или QA.

## Необязательный компонент

Настройка учреждения по умолчанию выключена. ADMIN разрешает компонент и задаёт
минимальную версию; сохранение проверяет revision и не перезаписывает чужую правку.
Прямые API-запросы и ранее установленный компонент подчиняются той же серверной политике.
Запрет останавливает только публичный показ и сохраняет канал обновлений; лекция не
завершается. Браузерный мастер остаётся доступным.

Компонент устанавливается явно один раз, работает в пользовательской графической
сессии с управляемым startup/tray, показывает собственную публичную сцену и временно
настраивает независимый выход. Он не перехватывает видеосигнал и не создаёт разные
изображения при настоящем Clone. Возврат исходной конфигурации учитывает текущую
топологию и ручные изменения; перед Clone требуется локальное подтверждение безопасности.

Исходники и проверяемый updater находятся в [projector-agent](../projector-agent/README.md).
Пакеты не предлагаются, пока нет подписанного совместимого выпуска. Цели Windows/macOS
сборки не равны проверенной поддержке физического оборудования. Обязательное обновление
загружается и проверяется заранее; замена/перезапуск выполняются после показа. Отдельный
процесс подтверждает здоровье новой версии после авторизованного poll, иначе откатывает
допустимую предыдущую версию либо оставляет компонент отключённым.

Подробный серверный протокол: [projector-helper-protocol.md](projector-helper-protocol.md).
Матрица физической проверки: [hardware-tests.md](../projector-agent/docs/hardware-tests.md).

## Источники платформенных ограничений

- [Chrome Window Management](https://developer.chrome.com/docs/capabilities/web-apis/window-management)
- [Screen sharing controls](https://developer.chrome.com/docs/web-platform/screen-sharing-controls)
- [TURN для WebRTC](https://webrtc.org/getting-started/turn-server)
- [Document Picture-in-Picture](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)

Headless и подставной Screen Details API проверяют переходы и изоляцию, но не физический
HDMI, системный fullscreen, реальный MAX или невидимость служебного окна при захвате монитора.
