# Временный стенд через ngrok

Пока нет VPS, стенд работает на машине разработчика за бесплатным туннелем ngrok. Схема
та же, что на VPS: prod-оверлей с обязательными секретами и Caddy, разводящий маршруты.
Отличие одно: HTTPS снаружи обеспечивает ngrok, а Caddy слушает HTTP на
`127.0.0.1:18088` (`TUNNEL_PORT`).

```
MAX / браузер ──HTTPS──> ngrok ──> Caddy :18088 ─┬─ /webhook/*      → max-adapter:8090
                                                 ├─ /api/*, /ws/*, /health → core:8080
                                                 └─ остальное       → web:80
```

## Запуск

```bash
brew install ngrok && ngrok config add-authtoken <токен из кабинета ngrok>   # один раз
sh deploy/stand/init-env.sh      # один раз: секреты в .env, токен бота спросит, если его нет
sh deploy/stand/tunnel.sh        # туннель + весь продукт; печатает публичный адрес
sh deploy/stand/tunnel.sh status # адрес и состояние контейнеров
sh deploy/stand/tunnel.sh stop   # остановить (данные в томах сохраняются)
```

Стенд запускается как отдельный проект compose `lecturer-stand` со своими томами и не
пересекается с локальным `docker compose up`.

## Что меняется при смене адреса

На бесплатном тарифе ngrok выдаёт новый адрес при каждом перезапуске туннеля.

| Что | Как обновляется |
|---|---|
| `MAX_WEBAPP_URL` (адрес в кнопке `open_app`) | автоматически: `tunnel.sh` передаёт новый домен в compose |
| `MAX_WEBHOOK_URL` (адрес вебхука) | автоматически: адаптер при старте удаляет старую подписку MAX и регистрирует новую |
| **Ссылка мини-приложения в кабинете MAX** | **вручную**: платформа MAX для партнёров → «Чат-боты» → бот → ⋮ → «Настройки». `tunnel.sh` пишет «АДРЕС ИЗМЕНИЛСЯ» и печатает нужное значение |
| CORS | менять нечего: веб и API на одном адресе, отдельной настройки CORS в core нет. WebSocket принимает любой origin (`LiveWebSocketConfig`). Если B-13 введёт список разрешённых адресов, туда нужно добавлять адрес туннеля |
| Ссылки, QR-коды, сообщения агентам и жюри | вручную |

Чтобы адрес не менялся, заберите в кабинете ngrok бесплатный статический домен
(Universal Gateway → Domains, один на аккаунт) и пропишите его в `.env`:

```
NGROK_DOMAIN=<имя>.ngrok-free.app
```

После этого ссылку в кабинете MAX достаточно задать один раз.

## Страница-предупреждение ngrok

Бесплатный ngrok отвечает на запросы с браузерным `User-Agent` своей HTML-страницей
«You are about to visit…» вместо приложения. Замер 24.09 на стенде:

| Запрос | Результат |
|---|---|
| браузерный UA, `GET /` | страница ngrok |
| браузерный UA + заголовок `ngrok-skip-browser-warning: 1` | приложение |
| `curl` (небраузерный UA) | приложение |
| вебхук MAX (серверный запрос) | доходит до адаптера |

Как обходится:

- в браузере — один раз нажать «Visit Site», дальше ngrok ставит cookie;
- в запросах из кода — заголовок `ngrok-skip-browser-warning` с любым значением или
  собственный `User-Agent`.

**Для webview MAX это может быть блокирующим.** Мини-приложение открывает сам MAX, и
выставить заголовок на первую загрузку страницы нельзя. Пользователь увидит
предупреждение ngrok вместо приложения. После перехода по «Visit Site» данные запуска
(`initData`, `start_param`) могут не дойти до приложения, и вход по MAX не сработает.
Проверять на телефоне первым делом. Если подтвердится, выхода два: VPS с доменом
(`deploy/stand/README.md`) или платный тариф ngrok без страницы-предупреждения.

## Почему не Cloudflare quick tunnel

Проверено 24.09 с машины разработчика (cloudflared 2025.2.1, туннель на Caddy):

- QUIC: `failed to dial to edge with quic: timeout` — UDP до Cloudflare не проходит;
- `--protocol http2`: `TLS handshake with edge error: EOF` — TCP 443 до узлов Cloudflare
  рвётся на рукопожатии;
- выданный адрес `*.trycloudflare.com` отвечает 530 «Cloudflare Tunnel error».

Кроме того, по документации Cloudflare quick tunnel не поддерживает Server-Sent Events,
а экран студента получает состояние лекции через SSE
(`/api/v1/student/sessions/{code}/events`).

## Переезд на VPS

Туннель и VPS используют одни и те же файлы. Разница только в оверлее и двух переменных:

```bash
sh deploy/stand/tunnel.sh stop                       # на машине разработчика
# на VPS, в клоне репозитория:
sh deploy/stand/init-env.sh --vps                    # добавит SITE_DOMAIN и ACME_EMAIL
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

После этого в кабинете MAX ссылка мини-приложения меняется на `https://<домен>/`. Вебхук
адаптер перерегистрирует сам. Данные тестового стенда на VPS не переносятся: там их
создаёт скрипт тестовых данных.
