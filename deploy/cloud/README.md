# Развёртывание в облаке

Здесь описано, как запустить Lecturer Assistant на одном арендованном сервере.
Всем управляет один скрипт: `deploy/cloud/lecturer.sh`.

## Что запускается

```
MAX / браузер ──HTTPS──> Caddy ─┬─ /webhook/*       → max-adapter (бот MAX)
                                ├─ /api/*, /ws/*    → core (Spring Boot)
                                └─ остальное        → web (React)
core ──> PostgreSQL, converter (PDF/PPTX → слайды), общий том с файлами
db-backup — ежедневная резервная копия базы и файлов
```

Это обычный монолит: семь контейнеров на одной машине. Распределённый профиль из
`deploy/scalable/` — лаборатория для нагрузочных опытов, для эксплуатации он не нужен.

## Какой сервер нужен

- Linux (Ubuntu 22.04/24.04 или похожий), **4 vCPU, 8 ГБ RAM, 40+ ГБ диска**.
  На 2 vCPU / 4 ГБ система запускается, но конвертация презентаций идёт медленно.
- Docker Engine и плагин Docker Compose ≥ 2.24.4.
- Бот MAX: его токен и публичное имя (кабинет MAX для партнёров).
- Один из двух способов выйти в интернет:
  - **domain** — свой домен, A-запись указывает на IP сервера, открыты порты 80 и 443.
    Сертификат Let's Encrypt Caddy получает и продлевает сам.
  - **tunnel** — туннель с постоянным адресом (например, Tuna). Порты открывать не нужно:
    туннель на сервере смотрит на `127.0.0.1:18088`, HTTPS даёт он.

MAX не принимает самоподписанные сертификаты, поэтому без домена или туннеля бот работать не будет.

## Установка

```sh
# Docker (если ещё нет)
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"   # затем перелогиньтесь

git clone https://github.com/MrHolly0/lecturer-assistant-v2.git
cd lecturer-assistant-v2
git checkout feature/cloud-deploy

sh deploy/cloud/lecturer.sh init    # режим, адрес, бот; секреты генерируются сами
sh deploy/cloud/lecturer.sh up      # сборка и запуск, первый раз 5–10 минут
sh deploy/cloud/lecturer.sh admin   # создать администратора (имя, email, пароль)
sh deploy/cloud/lecturer.sh lock-setup   # после проверки входа — закрыть создание админа
```

Затем в кабинете MAX для партнёров: «Чат-боты» → бот → ⋮ → «Настройки» →
ссылка мини-приложения `https://<ваш адрес>/`.

Для демонстрации вместо `admin` можно выполнить `seed`: он создаёт тестовых
администратора, преподавателя, ассистента, курс и лекцию. Пароли — `SEED_PASSWORD_*` в `.env`.

`.env` содержит все пароли и ключи. Он создаётся с правами 600 и не попадает в git;
сохраните его копию в менеджер паролей.

## Повседневные команды

| Задача | Команда |
|---|---|
| Состояние и проверка сайта снаружи | `sh deploy/cloud/lecturer.sh status` |
| Журналы (все или одного сервиса) | `sh deploy/cloud/lecturer.sh logs core` |
| Обновить до свежей версии ветки | `sh deploy/cloud/lecturer.sh update` |
| Резервная копия прямо сейчас | `sh deploy/cloud/lecturer.sh backup` |
| Остановить (данные сохраняются) | `sh deploy/cloud/lecturer.sh stop` |
| Любая команда docker compose | `sh deploy/cloud/lecturer.sh compose <аргументы>` |

После перезагрузки сервера всё поднимается само (`restart: unless-stopped`).
Раз в час cron проверяет сайт снаружи; результат — в `deploy/cloud/check.log`.
Для оповещений добавьте внешний монитор (например, UptimeRobot) на `https://<адрес>/health`.

## Резервные копии

Сервис `db-backup` раз в сутки сохраняет в `BACKUP_DESTINATION` каталог
`pair-<время>`: дамп базы, архив файлов презентаций и manifest с контрольными суммами.
Хранятся 14 дней (`BACKUP_KEEP_DAYS`). Копия на том же диске защищает от ошибок,
но не от потери сервера: подключите отдельный диск или регулярно копируйте каталог
наружу (например, в объектное хранилище провайдера).

Восстановление и проверка копий: [deploy/stand/README.md](../stand/README.md#restore-drill-в-отдельном-compose-проекте).

## Что где лежит

| Что | Где |
|---|---|
| Сайт и мини-приложение | `https://<адрес>/` |
| Проверка доступности | `https://<адрес>/health` |
| Вебхук MAX | `https://<адрес>/webhook/…` — случайный путь `MAX_WEBHOOK_PATH` в `.env` |
| Настройки и секреты | `.env` в корне клона |
| Compose-файлы | `docker-compose.yml` + `docker-compose.prod.yml` (+ `docker-compose.tunnel.yml` в режиме tunnel) |
| Лимиты памяти и CPU | [docs/runtime-budgets.md](../../docs/runtime-budgets.md) |

Снаружи открыты только 80/443 (в режиме tunnel — ничего). PostgreSQL и core слушают
только `127.0.0.1`.

Бот MAX при старте адаптера регистрирует вебхук на этот адрес и снимает прочие подписки.
Не запускайте две установки с одним токеном бота.
